执法记录仪系统

一个 Qt + FFmpeg 客户端项目，重点体现摄像头采集、实时预览、H.264 录像、本地回放、SQLite 数据管理与 MVC 分层组织能力。

C++Qt WidgetsQThreadFFmpegDirectShowH.264SQLiteMVC

项目概述

项目面向执法记录仪场景，实现摄像头采集、实时预览、录像、抓拍、视频查询、本地回放和日志查看等功能。视频处理逻辑封装在线程中，主界面通过 Qt 信号槽接收图像帧，避免采集、编码和文件处理阻塞界面交互。

摄像头采集FFmpeg DirectShow 打开本机摄像头
帧处理解码为 RGB32 预览，并转换为 YUV420P
录像写入H.264 编码，按帧数切分文件
本地管理SQLite 元数据、查询、回放与导出

核心实现

  • 封装 VideoProcessingThread，通过 FFmpeg dshow 输入设备采集摄像头流，循环读取视频帧并发送到界面显示。
  • 将解码后的帧转换为 RGB32 用于 Qt 实时预览，同时转换为 YUV420P 交给 H.264 编码模块写入录像。
  • 录像过程按 1500 帧进行自动切分，保存首帧封面并将视频路径、时间等元数据写入 SQLite，便于后续分页查询和回放。
  • 使用独立播放线程解码本地录像，支持播放、暂停和三档速度切换，降低长时间视频处理对主界面的影响。

MVC 分层

项目目录中包含 View、Controller 和 model 结构。界面层负责用户交互和展示，Controller 层负责业务调用，model 层封装用户数据与数据库访问，SingletonDB 用于管理 SQLite 连接。

View         // Qt 页面与控件交互
Controller   // 用户、查询等业务控制逻辑
model        // 数据模型与 SQLite 访问
SingletonDB  // 本地数据库连接管理

面试讲法

  • 我把摄像头采集和编码放到 QThread 中处理，界面只负责接收信号并刷新预览，避免主线程卡顿。
  • FFmpeg 采集链路里，输入端使用 DirectShow，显示端转 RGB32，编码端转 YUV420P，这样能同时满足预览和录像。
  • 录像不是一个文件无限写，而是按固定帧数切分，并把路径和封面信息写入 SQLite，便于列表查询和回放管理。
  • 项目按 View、Controller、model 分层组织，能把界面逻辑、业务控制和数据库访问拆开，后续维护更清晰。

源码事实边界

项目中的 MP4/AVI 处理更适合描述为“封装导出”或“容器转换”，不要夸成完整转码系统。真正的强点是摄像头采集、帧格式转换、H.264 录像、多线程预览和 SQLite 本地管理。
