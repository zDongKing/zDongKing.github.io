智慧停车系统

一个 Linux C++ 服务端项目，重点体现网络接入、业务任务分发、进程通信、数据库操作与应用层文件分片传输能力。

LinuxC++SocketepollpthreadMySQL共享内存消息队列信号量

项目概述

项目采用前置网络服务与后置业务服务的双进程结构。前置服务负责 TCP 连接接入、协议头解析、客户端连接标识维护和响应回写；后置服务负责业务任务分发、数据库读写和文件传输处理。两个进程之间通过共享内存、消息队列和信号量传递请求与响应数据。

客户端请求登录、车辆进出、查询、文件上传、心跳等
前置服务Socket 接入、epoll 监听、协议解析
IPC 通道共享内存、消息队列、信号量
后置服务任务工厂分发、MySQL 读写、响应返回

核心实现

  • 前置服务基于 Socket + epoll 处理 TCP 连接，将请求按 service_type + data_len + body 的格式解析并写入共享内存。
  • 后置服务通过任务工厂分发登录、验证码、注册、车辆进出、车辆查询、视频保存、目录查询、记录查询、文件传输、心跳等业务任务。
  • 通过 pthread 线程处理响应回写与超时检查，心跳链路用于维护客户端在线状态。
  • 业务数据通过 MySQL 写入和查询，覆盖用户、车辆、出入记录、视频目录与文件传输结果等信息。

文件分片传输

文件传输模块是项目中最适合展开讲的亮点。每个文件片段携带分片序号、总分片数、分片大小和文件大小等字段，服务端使用 map 缓存分片并自动覆盖重复序号。收到结束信号或最后一个分片后，服务端遍历检查缺失分片，缺片则返回缺失序号；完整则按序写入文件完成重组。

fragmentation_index   // 当前分片序号
fragmentation_total   // 总分片数量
fragmentation_size    // 当前分片大小
file_size             // 文件总大小
fragmentation_data    // 当前分片内容

面试讲法

  • 我主要负责服务端通信链路和业务任务联调，前置进程负责网络收发，后置进程负责业务处理，中间用 IPC 解耦。
  • 协议层没有只传 JSON，而是定义了固定协议头，包含业务类型和数据长度，后面接不同业务结构体。
  • 文件传输不是一次性发送大文件，而是应用层分片，每片都有序号和总片数，服务端能检测缺片并反馈需要补传的分片。
  • 如果被追问 TCP 粘包半包，可以说项目里主要做了定长协议头和业务体格式设计，完整的循环读包和连接级缓存还有继续优化空间。

源码事实边界

源码中定义了 13 个协议类型编号，但任务工厂实际分发的是 11 类业务请求。项目页面采用“业务任务分发”和“文件分片完整性校验”的表述，避免夸大成生产级完整 TCP 拆包框架。
